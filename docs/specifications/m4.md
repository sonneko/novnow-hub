# 仕様書: M4 コラボレーション（変更提案・課題・自動マージ・チャット・通知）

本書は novnow-hub の M4（コラボレーション）におけるユーザーから見える振る舞いを定義する。コードの実装情報は含まず、実装設計は設計書に委ねる。Phase 1（外部基盤を土台とした提供形態）のスコープとし、M5 以降の novnow 特化機能はスコープ外とする。

---

## 1. 目的とスコープ

### 1.1 目的とスコープ

M4 の目的は、公開された作品を複数の利用者で共同制作できるよう、変更提案・課題・チャット・通知といったコラボレーション機能を提供することである。M4 の完了条件は「派生 → 変更提案 → 承認 → 自動マージ → 通知、の一連の流れが本番環境で確認できること」である。

スコープ内：変更提案の作成・レビュー・取り込み、課題の管理、自動マージの予約・取消・状態表示、チャットルームとメッセージ、通知センターと未読バッジ、GitHub Webhook 受信による公開ページ再生成とキャッシュ失効。

スコープ外：派生ツリーの可視化、novnow 診断・エクスポート、セットアップ URL、派生元の表示・管理（これらは M5 以降）。

---

## 2. 変更提案（プロポーザル）

### 2.1 変更提案の作成とレビュー

利用者は派生作品上で行った変更を、親プロジェクトへ変更提案として送れる。変更提案はタイトル・説明・差分・会話・状態（オープン／承認済み／取り込み済み／却下）を持つ。差分は本文テキストと設定ファイルの単位で表示され、レビューはインラインコメントと全体コメントの両方をサポートする。親プロジェクトの所有者は提案の差分・提案者・発言を確認し、承認・コメント・却下ができる。

### 2.2 差分と診断の表示

変更提案の差分には、novnow 形式の診断結果（新たに混入した誤りや解消された誤り）を併せて表示する。診断結果は変更提案の必須チェックとして利用でき、診断エラーがある場合は取り込みをブロックするか警告を表示する。

---

## 3. 課題（イシュー）

### 3.1 課題の管理

利用者は作品に対して課題（問題・要望・議論）を作成できる。課題はタイトル・本文・ラベル・状態（オープン／クローズ）・担当者・会話を持ち、作品ごとのテンプレートを用意できる。課題から変更提案への紐付け（この提案は課題 X を解決する）を記録し、関連づけて閲覧できる。

---

## 4. 自動マージ

### 4.1 自動マージの予約と状態表示

変更提案ごとに「条件を満たしたら自動で取り込む」を予約できる。条件は必要な承認数（既定 1）、必須チェックの通過、競合がないことの組合せで指定する。予約の取消も行え、状態（予約済み／評価中／取り込み済み／条件未達／競合で失敗）は提案画面に表示する。自動マージが発火したことは、誰が操作したかを含めて記録に残す。

---

## 5. チャット

### 5.1 チャットルームとメッセージ

プロジェクトごとに複数のチャットルームを持てる。ルームは全体／制作／雑談など任意の名前で作成でき、メッセージは時系列表示・未読バッジ・編集・削除（論理削除）をサポートする。メンション（@表示名）で通知を送る。チャットは揮発性の低い付随データとして hub 管理の軽量ストアに保存され、外部基盤には保存しない。

---

## 6. 通知

### 6.1 通知センターと未読バッジ

hub 内の通知は通知センターに集約する。対象は派生作品の作成・変更提案・その承認/取り込み/自動マージ結果・課題の作成/コメント・チャットのメンションなどである。通知は未読/既読/全既読ができ、種別でフィルタでき、未読バッジで数を表示する。一覧はページネーションを持つ。

### 6.2 通知のファンアウト

ドメインイベント（プロジェクト更新・提案承認など）が発生した場合、関係する利用者へ通知がファンアウトされる。通知チャネルは既定で hub 内のみとし、メール・Web Push 等の追加チャネルはオプトインで将来拡張できる。

---

## 7. GitHub Webhook 受信による公開ページ再生成

### 7.1 Webhook 受信とキャッシュ失効

外部基盤（GitHub）からの Webhook 受信（署名検証付き）により、公開ページの再生成とキャッシュ失効を行う。Webhook イベントに応じて対象プロジェクトの公開ページを再描画し、CDN 等のキャッシュを無効化する。Webhook の処理結果はログに残し、失敗時はリトライまたは手動再実行の導線を提供する。

---

## 8. 非機能要件

### 8.1 セキュリティ

Webhook 受信には署名検証を行い、なりすましを防ぐ。変更提案・課題・チャットの内容を、認可を経ずに返さない。非公開プロジェクトに関わるイベントは関係者以外に通知しない。

### 8.2 性能と可用性

通知ファンアウトと書き込み系 API の処理はキュー化し、同時実行数を制限する。Webhook 受信による再生成は非同期に行い、閲覧をブロックしない。
