# 仕様書: M3 薄いスライス—公開と閲覧（Phase 1 最小）

本書は M3（薄いスライス：公開と閲覧）のユーザーから見える振る舞いを定義する。コードの実装情報は含まず、実装設計は設計書に委ねる。Phase 1（外部基盤を土台とした提供形態）の最小スコープとし、M4 以降のコラボレーション機能はスコープ外とする。

---

## 1. 目的とスコープ

M3 の完了条件は「非エンジニアが zip をアップロードして公開でき、第三者が URL を開いて本文を読めること（本番相当環境）」である。バックエンド骨格・保管基盤への接続・公開フロー・閲覧体験・プロジェクト発見・セットアップ URL を実装する。

M3 の範囲外：変更提案・課題・チャット・通知・自動マージ・派生ツリー・novnow 診断・エクスポート（これらは M4 以降）。

---

## 2. 公開フロー

### 2.1 新規公開の手順

利用者は次を順に行うだけで作品を公開できる。

1. 外部アカウントでサインインする（本プラットフォーム独自のパスワード認証は提供しない）。
2. 手元の作品フォルダを選択するか、zip をアップロードする。
3. タイトル・説明・ライセンス・公開範囲を確認し、公開を確定する。

公開処理は、作品を保管基盤に登録し、プロジェクトとして記録し、公開ページを生成する一連の操作である。途中で失敗した場合は中間状態を残さず、やり直せること。

hub はアップロードされた zip に対し novnow 本体の仕様（novnow リポジトリの `specifications/project.md` §4.2・§4.3）と同一の軽量検証を行い、公開可否を判定する。検証内容は必須ファイル（`project.toml`・`characters.md`・`words.md`・`materials/index.json`・`plots/all.cnov`）・必須ディレクトリ（`contents/`・`plots/`）の存在、`project.toml` が TOML として読めて `schema_version` が `2` または省略（`2` より大きい版は拒否）、文書ファイルの UTF-8 妥当性である。任意パスの欠落・未知ファイル・README は拒否理由にせず、不足ファイルを hub が自動生成して補うこともない。検証失敗時は中間状態を残さず、欠落・不正ファイルの一覧を返す。

### 2.2 公開完了後の提示

公開完了後、次の 2 つを提示する。

- 公開ページの URL（本プラットフォームのドメイン上。アカウントなしで閲覧可能）
- セットアップ URL（専用アプリが作品を開くための URL）

---

## 3. 閲覧体験

### 3.1 プロジェクトページ

公開ページには、タイトル・説明・作者・ライセンス・最新更新日時・派生数・主要なファイル構成を表示する。本文ビューでは作品の本文を読者向け体裁に整形して表示する。編集導線は所有者・共同制作者にだけ表示する。設定資料（登場人物・用語辞書・プロット概要など）は作者が「公開資料」として選んだものだけを表示し、既定は非公開とする。

### 3.2 読者ビュー

公開ページの URL を開くだけで、アカウント・専用アプリなしで本文を通読できる。読書体験はダーク／ライトテーマと文字サイズ調整をサポートする。作品固有の非表示指定（注釈・コメント）は読者ビューに現れない。

### 3.3 事前描画とキャッシュ

公開ページはキャッシュ配信を前提とし、初回表示は国内モバイル回線で 2 秒以内の Largest Contentful Paint を目標とする。

---

## 4. プロジェクト発見

### 4.1 一覧

公開作品の一覧は、新着・更新順・人気順で並び替えられる。ページネーションは明示的な「次へ」で行う。

### 4.2 検索

検索は、キーワード・タグ・ライセンス・作品の種別で絞り込める。第 1 段階では本プラットフォーム側の軽量インデックスで実現し、外部検索に依存しすぎない。ランキングやトレンドなど重い集計は提供しない。

---

## 5. セットアップ URL

セットアップ URL にはプロジェクトの識別情報のみを含み、認証情報や個人情報を含まない。ブラウザ版には通常の URL として、デスクトップ版には OS のカスタムスキームで渡す。セットアップに失敗した場合は、失敗工程と手動での取得方法を示す。

---

## 6. 非機能要件（M3 適用）

### 6.1 セキュリティ

認証情報はクライアントに永続させず、API 側で安全に管理する。非公開作品の内容を認可を経ずに返さない。存在しない・非公開のプロジェクトは 404 で応答し、存在を秘匿する。アップロードされた zip は検証後に破棄し、恒久保存しない。なりすまし・クリックジャッキング・スクリプト埋め込み・パス traversal（zip 内の `../` 等）への対策を行う。

### 6.2 性能と可用性

API の読み取り系エンドポイントのサーバ処理時間は p95 で 200 ミリ秒以内を目標とする（外部 API 往復を除く構成では 100 ミリ秒以内）。公開ページの静的部分はキャッシュ配信を前提とし、基盤の障害時でも配信を継続する。書き込み系操作のみ一時的に利用不能とし、読み取り専用に縮退する。
