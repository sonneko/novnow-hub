# 仕様書: M7 運用・品質・OSS 公開準備

本書は novnow-hub の M7（運用・品質・OSS 公開準備）におけるユーザーから見える振る舞いを定義する。コードの実装情報は含まず、実装設計は設計書に委ねる。Phase 1（外部基盤を土台とした提供形態）のスコープとし、M6 で導入したマルチプラットフォーム対応の上に運用・品質・公開準備を載せる。

---

## 1. 目的とスコープ

### 1.1 目的とスコープ

M7 の目的は、novnow-hub を OSS として一般公開できる状態にすることである。M7 の完了条件は「OSS として一般公開できる状態」である。

スコープ内：本番デプロイ（Workers + D1 を既定、VPS + Docker を代替）と外形監視・バックアップ・鍵ローテーション手順、CI の拡張（契約互換性検査・脆弱性検査・カバレッジゲート）、セキュリティレビュー（zip 取込・CSP・トークン暗号化・権限判定）と依存ライセンスの棚卸し、ドキュメント整備（セルフホストガイド・運営ポリシー・CHANGELOG）と初回リリース、性能目標の実測検証（LCP・API p95・検索）とコスト実測。

スコープ外：M8 以降の大規模機能追加（Phase 2 への移行、セルフホスト配布物の拡充、高度な検索、プラグイン機構等は plans.md の「将来の拡張点」に委ねる）。

---

## 2. 本番デプロイとインフラ運用

### 2.1 本番デプロイ

本番デプロイは Workers + D1 を既定とし、VPS + Docker を代替構成とする。デプロイパイプラインにより、コード変更を本番環境に安全に適用できる。

### 2.2 外形監視

公開ページおよび hub API の外形監視を行い、サービスの可用性を検知する。監視結果はアラートとして通知される。

### 2.3 バックアップと鍵ローテーション

重要データのバックアップ手順を定義し、定期的に実行する。暗号鍵・トークン等の秘密情報は定期的にローテーションする。

---

## 3. CI の拡張と品質ゲート

### 3.1 契約互換性検査

OpenAPI 契約の互換性検査（oasdiff 相当）を CI に組み込み、破壊的変更を検出する。

### 3.2 脆弱性検査とカバレッジゲート

`cargo audit`／`npm audit` による脆弱性検査とテストカバレッジゲートを CI に組み込み、品質を担保する。

---

## 4. セキュリティレビューと依存ライセンス

### 4.1 セキュリティレビュー

zip 取込・CSP・トークン暗号化・権限判定についてセキュリティレビューを行い、脆弱性を修正する。

### 4.2 依存ライセンスの棚卸し

使用する依存ライブラリのライセンスを棚卸し、OSS として公開するにあたって問題がないかを確認する。

---

## 5. ドキュメント整備と初回リリース

### 5.1 セルフホストガイド

novnow-hub をセルフホストするためのガイドを整備し、利用者が自前でデプロイできるようにする。

### 5.2 運営ポリシーと CHANGELOG

公開インスタンスの運営ポリシー（公開基準・削除基準・著作権対応）を明記し、CHANGELOG を整備する。

### 5.3 初回リリース

OSS としての初回リリースを行い、一般公開する。

---

## 6. 性能目標の実測検証とコスト

### 6.1 性能目標の実測

LCP・API p95・検索などの性能目標を実測し、目標値を達成しているかを検証する。

### 6.2 コスト実測

運用コストを実測し、月額数千円以下というコスト制約を満たしているかを確認する。

---

## 7. 非機能要件

### 7.1 セキュリティ

zip 取込のパス traversal・CSRF・XSS・クリックジャッキングへの対策を行う。トークン暗号化により秘密情報を保護する。権限判定により非公開対象へのアクセスを制限する。

### 7.2 性能と可用性

公開ページの初回表示は国内モバイル回線で 2 秒以内の Largest Contentful Paint を目標とする。hub API の読み取り系エンドポイントのサーバ処理時間は p95 で 200 ミリ秒以内を目標とする。月間可用性目標は 99.5% とする。

### 7.3 コスト制約

共有インスタンスの運用コストは、GitHub とサーバーレス無料枠＋最小限の有償枠のみで、月額数千円以下を目安とする。定時実行（cron）の頻度・実行時間に上限を設け、従量課金の暴走を防ぐ。
