# 仕様書: M5 novnow 特化機能（セットアップ URL・派生ツリー・診断）

本書は novnow-hub の M5（novnow 特化機能）におけるユーザーから見える振る舞いを定義する。コードの実装情報は含まず、実装設計は設計書に委ねる。Phase 1（外部基盤を土台とした提供形態）のスコープとし、M4 で導入したコラボレーション機能の上に novnow 特化の機能を載せる。

---

## 1. 目的とスコープ

### 1.1 目的とスコープ

M5 の目的は、派生作品のツリー構造を可視化し、セットアップ URL で novnow アプリが作品を即座に開き、novnow 診断・エクスポートを非同期ジョブで提供し、変更提案差分に診断結果を付与し、公開前検証を本格化することである。M5 の完了条件は「セットアップ URL 一発で novnow アプリが作品を開き、診断結果が変更提案フローに乗ること」である。

スコープ内：派生ツリー UI（/derivatives）、派生レコードと派生元連携、セットアップ URL 発行と解決（/projects/{id}/setup、/setup/resolve）と novnow アプリ側ハンドラ仕様、novnow 診断・エクスポートの非同期ジョブ基盤（JobPort）と実行環境、変更提案差分への novnow 診断差分の付与、公開前検証の本格化（novnow check 相当の診断を必須チェックに連動）。

スコープ外：PWA 化、Tauri secure storage へのセッション保管、インストーラ署名（これらは M6 以降）。

---

## 2. 派生ツリーと派生レコード

### 2.1 派生ツリー UI（/derivatives）

各プロジェクトページに「派生」タブを設け、自分の直接の子作品・孫以降・兄弟作品を木構造で表示する。各ノードはタイトル・作者・更新日・派生可否を示す。原作者は派生作品の存在を通知で知る。通知は設定で切れる。

### 2.2 派生レコードと派生元連携

派生作品は派生元との対応関係を hub が記録する。派生の派生（孫作品）も同様に作成でき、派生元の連鎖を保持する。派生時にライセンス継承の確認・作品名の既定値・説明の初期値を提示する。派生作品の初回公開時も novnow 形式の検証を通す。

---

## 3. セットアップ URL

### 3.1 セットアップ URL 発行（/projects/{id}/setup）

セットアップ URL はプロジェクトの識別情報のみを含み、認証情報や個人情報を含まない。ブラウザ版には通常の URL として、デスクトップ版には OS のカスタムスキームで渡す。セットアップに失敗した場合は、失敗工程と手動での取得方法を示す。

### 3.2 セットアップ URL 解決（/setup/resolve）

公開ページのセットアップ URL を解釈し、取得元と手順情報を返す。アプリが公開 URL から出発できるようにするため、認証不要の公開 tarball を既定とし、私設の場合は短期失効トークン付き URL を発行する。いずれの場合も hub のセッションをアプリへ渡さない。

### 3.3 novnow アプリ側ハンドラ仕様

novnow アプリ（デスクトップ／ブラウザ）がセットアップ URL を解釈し、作品の取得 → ローカルへの配置 → novnow プロジェクトとしての初期化検証 → エディタを開くを自動で行う。URL ひとつでセットアップ済みの作品をアプリで開けること。

---

## 4. novnow 診断・エクスポート

### 4.1 非同期ジョブ基盤（JobPort）

novnow 診断（novnow check 相当）や本文のエクスポートは非同期ジョブとして実行し、完了を通知で知らせる。hub 自身は novnow 本体の全機能を再実装しない。重い処理はキュー化し、同時実行数を制限する。

### 4.2 診断の実行環境

診断の実行環境は、novnow の WASM 実行を既定とし、利用できない場合は GitHub Actions 上の novnow CLI をフォールバックとする。診断結果は「点検」タブに表示できる。

### 4.3 エクスポート

hub 上で本文のエクスポート（注釈除去済みテキスト／Markdown）を生成できる。生成物はダウンロードまたは変更提案に添付できる。

---

## 5. 変更提案差分への novnow 診断差分

### 5.1 診断差分の付与

変更提案の差分には、novnow 形式の診断結果（新たに混入した誤りや解消された誤り）を併せて表示する。診断結果は変更提案の必須チェックとして利用でき、診断エラーがある場合は取り込みをブロックするか警告を表示する。

---

## 6. 公開前検証の本格化

### 6.1 novnow check 相当の診断を必須チェックに連動

公開前の novnow 点検（診断エラー 0 件）を変更提案の必須チェックとして登録できる。チェック結果は変更提案に表示され、自動マージの条件に使える。重いチェックは非同期に行い、提案をブロックしすぎない。

---

## 7. 非機能要件

### 7.1 セキュリティ

Webhook 受信には署名検証を行い、なりすましを防ぐ。変更提案・課題・チャットの内容を認可を経ずに返さず、非公開プロジェクトに関わるイベントは関係者以外に通知しない。

### 7.2 性能と可用性

通知ファンアウトと書き込み系 API はキュー化し、同時実行数を制限する。診断・エクスポートなどの重い処理は非同期に行い、閲覧をブロックしない。
