# 設計書: M6 マルチプラットフォーム（Tauri・PWA）

本書は `REF:docs/specifications/m6.md` の各節に対応する実装設計を述べる。見出しは仕様書と一致させ、各 `###` 節の冒頭に実装状態を置く。契約の唯一の正は `REF:api/openapi.yaml`（OpenAPI 3.1）であり、M6 は主にクライアントサイド（Tauri v2 デスクトップビルド・PWA 化・セッション保管・インストーラ署名）の機能であるため、API 契約への変更は不要である。GitHub へのアクセスはアダプター層の背後に隠され、API 契約・フロントエンド・利用者体験には GitHub の概念を漏らさない。

---

## 1. 目的とスコープ

### 1.1 目的とスコープ

状態: 実装完了

M6 は Phase 1 のマルチプラットフォーム対応を実装する。Web アプリ（Astro + Svelte + TypeScript）と同一のコードベースを Tauri v2 でデスクトップアプリとしてパッケージングし、PWA 化によるオフライン閲覧を実現する。Phase 2 ではアダプター差し替えのみで自前バックエンドへ移行でき、API 契約とクライアントは変更しない。

---

## 2. Tauri v2 デスクトップビルド

### 2.1 デスクトップアプリの提供

状態: 実装完了

Tauri v2 により、Web アプリと同一のコードベースを Windows／macOS／Linux 向けデスクトップアプリとしてパッケージングする。見た目と操作は Web 版と共通とし、Tauri の WebView を使用してレンダリングする。

### 2.2 配布パイプライン

状態: 実装完了

デスクトップアプリのビルドを CI パイプラインで自動化する。各プラットフォーム向けにビルド成果物を生成し、配布可能な形式で出力する。ビルド成果物の署名・配布は §5 と連携する。

---

## 3. PWA 化

### 3.1 PWA マニフェストとオフラインシェル

状態: 実装完了

PWA マニフェスト（manifest.json）を提供し、ブラウザからアプリとしてインストールできるようにする。オフラインシェルにより、ネットワークが不安定な環境でもアプリのシェル部分を表示できる。Service Worker により静的リソースをキャッシュする。

### 3.2 読者ビューのオフライン閲覧

状態: 実装完了（読者ビュー本文の CacheStorage 保存とオフライン表示は M3 の事前描画と ETag キャッシュ（PR #19）の既存仕組みを再利用。PWA のマニフェスト・Service Worker オフラインシェルを実装し、インストール済みアプリとしてのオフライン閲覧経路を完成）

読者ビュー（公開ページの本文）をオフラインで閲覧できる。キャッシュ戦略により、既に読んだ公開ページの本文をオフラインでも表示できる。キャッシュキーはプロジェクト識別子と更新 ETag で構成する。なお、このキャッシュ戦略（プロジェクト識別子と更新 ETag をキーとする読者ビュー本文の CacheStorage 保存とオフライン表示）は M3 の事前描画と ETag キャッシュ（PR #19）で先行実装済みであり、M6 では PWA のマニフェスト・オフラインシェル（Service Worker）を整え、インストール済みアプリとしてのオフライン閲覧経路を完成させる。

---

## 4. セッション保管とセットアップ URL 受信

### 4.1 Tauri secure storage へのセッション保管

状態: 実装完了

デスクトップアプリでは、セッション情報（アクセストークン・更新トークン）を Tauri secure storage（macOS Keychain / Windows Credential Manager / Linux Secret Service 等）に保管する。ブラウザ版とは異なり、メモリのみに依存せず、アプリ再起動後もセッションを維持できる。セッション情報は平文で露出しない。**実装（M7 セキュリティレビュー・タスク1）**: `src-tauri/src/lib.rs` の `SecureStorage` は `keyring` v3 で OS キーチェーンを主backとし、キーチェーン backend が利用できない環境では AES-256-GCM による暗号化ファイル（`app_data_dir` 配下の `.enc`）へフォールバックする。暗号化鍵はマシン固有エントロピー（machine-id 等）＋パス＋定数ソルトから導出し、パス単体からの鍵導出を防止する。平文ファイルは廃止し、平文露出を排除する（詳細は `REF:docs/handoff.md` 判断 16・18 を参照）。

### 4.2 カスタムスキームでのセットアップ URL 受信

状態: 実装完了

デスクトップアプリは OS のカスタムスキームでセットアップ URL を受信し、作品の取得 → ローカルへの配置 → novnow プロジェクトとしての初期化検証 → エディタを開くを自動で行う。URL ひとつでセットアップ済みの作品をアプリで開けること。URL にはプロジェクト識別情報のみを含み、認証情報や個人情報を含まない。

## 5. インストーラ署名およびストア配布

### 5.1 インストーラ署名またはストア配布の方式

状態: 実装完了

デスクトップアプリのインストーラに署名を付与するか、ストア配布の方式を決定し実装する。署名により、ユーザーはインストーラの出所を検証でき、改ざんを防ぐ。

### 5.2 配布方式の決定

状態: 実装完了

Phase 1 では、インストーラ署名またはストア配布のいずれかを既定の配布方式とし、利用者が安全にデスクトップアプリをインストールできるようにする。方式の決定は M7 の運用・公開準備と整合させる。

既定の配布方式は「CI で生成したインストーラ」とし、署名は **M7 セキュリティレビュー（タスク2）で実装**する。方式は **Tauri ネイティブ bundle 署名**を採用し、署名設定は `tauri build --config` で**条件付き注入**する（`tauri.conf.json` 本体には署名設定を載せない）。macOS は `bundle.macOS.signingIdentity` と Apple 資格（`APPLE_ID`/`APPLE_PASSWORD`/`APPLE_TEAM_ID`）により codesign＋ノタリゼーション、Windows は pfx をローカル証明書ストアに導入し `bundle.windows.certificateThumbprint` により署名する。**secrets 未設定時は署名設定を作らず unsigned フォールバック**でビルドし、PR ビルドは緑になる。Linux には標準的なインストーラ署名機関が無く、Phase 1 は未署名配布とする。証明書の発行・登録手順（sonneko のみ実施可能）は `REF:docs/handoff.md` 判断 17 を参照。デスクトップビルドの検証は CI のデスクトップパイプライン（`REF:.github/workflows/desktop.yml`、Linux/Win/macOS）で行う。サンドボックス環境では Tauri のバイナリビルドを実行できない（crates.io 到達不可・`tauri`/`iota_stronghold` 未ベンダー・webkit2gtk/gtk3 未導入）ため、検証は CI の実行結果に委ねる。

**CI ビルドの障害履歴**: PR #52 の初回 Desktop ワークフローは 3 プラットフォームすべてで失敗した。真因は (1) `stronghold` クレートの誤用（正しくは `iota_stronghold`）、(2) `tauri build --bundle` の引数誤り（正しくは `--bundles`）、(3) `tauri::State<T>` の lifetime 欠落（E0726、正しくは `tauri::State<'_, T>`）であった。原因特定の経緯・修正の詳細は `REF:docs/history.md` の `M6-MULTIPLATFORM` エントリに記録する（設計書には現行の設計判断のみを残す）。セッション保管は、依存関係が重く障害要因になり得た IOTA Stronghold（`iota_stronghold`）・`keyring` を M6 では排し、依存関係ゼロのファイルベース実装で要件の核心を満たした。その後 M7 セキュリティレビュー（判断 16・18）で OS キーチェーン主体＋暗号化ファイルのフォールバックへ置き換えている（§4.1）。

## 6. 非機能要件

### 6.1 セキュリティ

状態: 実装完了

セッション情報はクライアント側の安全なストレージに保管し、平文で露出しない。インストーラ署名により改ざんを防ぐ。GitHub へのアクセスはアダプター層の背後に隠し、API 契約・フロントエンド・利用者体験には GitHub の概念を漏らさない。

### 6.2 性能と可用性

状態: 実装完了

デスクトップアプリの起動とオフライン閲覧は、ネットワークに依存せず動作する。PWA のキャッシュ戦略により、読者ビューのオフライン閲覧を実現する。
