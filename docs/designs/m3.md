状態: 実装完了（バックエンド骨格・公開フロー・閲覧体験・一覧検索を実装。詳細は各節を参照。REF:docs/plans.md#m3-thin-slice）

## 2. 公開フロー

### 2.1 新規公開の手順

状態: 実装完了（公開ウィザード UI は PR #8、zip 取込モジュールは PR #41 で実装済み。multipart 取込・軽量検証・保管単位作成・hub 登録・公開ページ生成まで実装済み、REF:docs/plans.md#m3-thin-slice）

サインイン後の公開フローは、作品のアップロード（zip またはフォルダ）→ 軽量検証（必須要素・文字コード・マニフェストの整合性）→ 保管単位の作成 → プロジェクト登録 → 公開ページ生成 の順で処理する。各工程はトランザクション的に扱い、いずれかで失敗したら中間状態を残さずエラーを返す。検証は保管基盤への投入前に行い、壊れた初期状態を作らない。

軽量検証は novnow 本体の仕様（novnow リポジトリの `specifications/project.md` §4.2・§4.3）と同一の判定を行い、hub 独自の必須要素は発明しない。zip 展開後に次の点を検査し、いずれか失敗時は保管単位を作成せずエラー（`400`、欠落・不正ファイルの一覧を含む）を返し、zip は検証後に破棄する（仕様 §6.1）。

- **必須ファイル**: `project.toml`、`characters.md`、`words.md`、`materials/index.json`、`plots/all.cnov` のすべてが存在すること。欠けると検証失敗とする。
- **必須ディレクトリ**: `contents/`（空でも可）・`plots/` が存在すること。zip のディレクトリ entry（末尾 `/`、または Unix モードのディレクトリ）はファイル化せず `dirs` に分類し、必須ディレクトリの存在判定はファイルの有無とディレクトリ entry の存在の双方で行う。空の `contents/` はディレクトリ entry のみでも受理する。`__MACOSX/`・`.DS_Store` などのノイズ entry は展開結果から除外する。
- **マニフェスト（`project.toml`）**: TOML として読めること。複数行の値（配列・三重引用符のマルチライン文字列）を含むマニフェストも `[`・`]` の深さと引用符状態を行間で追跡して平衡を検証し、読めること。`schema_version` の検査は**トップレベルのキーのみ**とし、テーブル内の `schema_version` は検査対象外（省略扱い）とする。`schema_version` が `2` または省略は OK、`2` より大きい版は拒否（novnow 本体の更新が必要な版）。TOML として読めないマニフェスト（不平衡な配列・閉じていない文字列等）は拒否する（hub の検証は「公開してよいか」の判定であり、壊れたマニフェストの作品を公開しない）。
- **文字コード**: 文書として認識するファイルが UTF-8 として妥当であること。不正バイトがあれば該当ファイルを列挙して拒否する。

**拒否理由にしないもの**: 任意パス（`ideas.md`・`prompts/`・`agents/`・`exports/`・`.novnow/`）の欠落、仕様が定義しない未知のファイル（無視し、削除・改名・上書きしない）、README（novnow 形式に存在しない）は拒否理由にしない。不足ファイルを hub 側で自動生成して補うこともしない（作者の書いていない内容を発明して保管基盤に入れることは「壊れた初期状態を作らない」設計方針に反する）。本文 `.cnov` のパース（構文診断）までの深い診断は軽量検証では行わず、M4 以降の novnow 診断に委ねる。判断記録は `REF:docs/handoff.md` §4 判断 5 を参照する。

軽量検証を通過した zip は保管基盤へコミットする。ファイルのエンコーディングは UTF-8 として妥当ならテキスト、そうでない（バイナリ相当）は Base64 でコミットし、内容を壊さない（黙って文字化けさせない）。保管単位の作成後、コミット・公開範囲設定のいずれかで失敗した場合、中間状態を残さないために保管単位を削除する。削除自体が失敗した場合はその旨をエラーに含める。判断記録は `REF:docs/handoff.md` §4 を参照する。

### 2.2 公開完了後の提示

状態: 実装完了（公開完了レスポンスに公開ページ URL とセットアップ URL を含む、REF:docs/plans.md#m3-thin-slice）

公開完了レスポンスに公開ページ URL とセットアップ URL を含める。URL 生成はプロジェクト識別子（ULID 互換の不透明文字列）から機械的に行い、認証情報を含めない。公開ページ URL は `{HUB_PUBLIC_BASE}/reading/?projectId={projectId}` を機械生成する（判断記録は `REF:docs/handoff.md` §4 判断 1）。セットアップ URL は `/setup/resolve?u=…` 形式を既定とする。判断記録は `REF:docs/handoff.md` §4 判断 1 を参照する。

## 3. 閲覧体験

### 3.1 プロジェクトページ

状態: 実装中（フロントエンドのプロジェクトページ UI は実装済み。メタ情報を返すネイティブサーバーのルートは `GET /projects` 一覧のみで、詳細ページ用の `GET /projects/{projectId}/tree`・`/file`・`/releases`・`/setup` は未配線。判断: `REF:docs/handoff.md` §4 判断 27、REF:web/src/components/pages/ProjectPage.svelte）

プロジェクトページは事前生成またはサーバー側レンダリングで配信し、メタ情報（タイトル・説明・作者・ライセンス・更新日時・派生数）とファイル構成を表示する。本文ビューは閲覧専用の読者ビューとして実装し、編集導線は認証・役割に基づき所有者・共同制作者にだけ出し分ける。設定資料は作者が公開を選んだものだけを出力する。

### 3.2 読者ビュー

状態: 実装完了（REF:web/src/pages/reading/index.astro）

読者ビューは `/reading` 配下のルートで提供され、公開ページの URL を開くだけで本文を通読できる。ダーク／ライトテーマと文字サイズ調整をサポートし、作品固有の非表示指定（注釈・コメント）は表示しない。UI 骨格は M2 で導入済みであり、M3 ではバックエンド API との接続とキャッシュ配信を整える。

### 3.3 事前描画とキャッシュ

状態: 実装完了（REF:web/src/pages/projects/index.astro, REF:web/src/pages/reading/index.astro, REF:web/src/components/pages/ProjectPage.svelte, REF:web/src/components/pages/ReaderPage.svelte, REF:web/src/lib/reader-cache.ts）

Astro の静的ビルドで公開プロジェクト・読者ページの HTML シェルを事前描画し、CDN 配信できる形にする。公開プロジェクトページでは読者リンクへのフォーカス／ポインター進入時に既存の `GET /projects/{projectId}/reading` を先読みする。読者向けに整形済みの `ReadingDocument` は CacheStorage にプロジェクト ID と応答の ETag を含むキーで保存し、`/reading` では保存済み本文を先に表示しながら同じ OpenAPI エンドポイントで再検証する。新しい ETag を受け取ったときは旧版を削除し、404 では公開を取り下げた可能性があるため保存済み本文も消去する。API 契約は変更しない。

## 4. プロジェクト発見

### 4.1 一覧

状態: 実装完了（バックエンドの軽量インデックス・カーソルページネーション・ソート選択を実装、REF:docs/plans.md#m3-thin-slice）

一覧は更新日時降順＋ID 降順の複合ソートでカーソルページネーション（`limit` 上限 100）を適用し、並び替えキー（新着・更新順・人気順）をクエリで選択できる。バックエンドはインメモリ登録簿（`ProjectRegistry`）のスナップショットを走査する軽量インデックス（`project_index`）で一覧を実現し、`GET /projects`（`sort`・`cursor`・`limit`）を公開する（認証不要、契約 `listProjects`）。公開作品のみを対象とし、総件数は返さず `nextCursor` で「次へ」を返す。フロントエンドは `REF:web/src/components/pages/ProjectsPage.svelte` と `REF:web/src/lib/project-index.ts` で一覧表示・カーソル展開・取得済みページ内のフィルタを実装する。

### 4.2 検索

状態: 実装完了（キーワード・タグ・ライセンスの軽量インデックス検索を実装。作品種別の絞り込みは契約に項目が無いため対象外、REF:docs/plans.md#m3-thin-slice）

検索はキーワード・タグ・ライセンスで絞り込み、軽量インデックス（`project_index`）上で実行する。`GET /search/projects`（`q`・`license`・`tag`・`sort`・`cursor`・`limit`）を公開する（認証不要、契約 `searchProjects`）。キーワードはタイトル・作者ハンドル・説明・タグを部分一致（関連度順）、ライセンスは列挙値、タグは部分一致で絞り込む。総件数は返さず「さらに読み込む」方式とする。作品種別の絞り込みは M3 では契約に項目が無いため対象外とする（判断 `REF:docs/handoff.md` §4）。

## 6. 非機能要件（M3 適用）

### 6.1 セキュリティ

状態: 未実装・実装計画済み（REF:docs/plans.md#m3-thin-slice）

認証トークンはクライアントに永続させず API 側で管理する。非公開対象へのアクセスは 404 で応答し存在を秘匿する。zip は検証後に破棄し、パス traversal や CSRF・XSS・クリックジャッキングへの対策を行う。

### 6.2 性能と可用性

状態: 未実装・実装計画済み（REF:docs/plans.md#m3-thin-slice）

API 読み取り系のサーバ処理時間は p95 で 200 ミリ秒以内を目標とする。公開ページの静的部分はキャッシュ配信を前提とし、基盤障害時でも配信を継続し、書き込み系のみ一時利用不能とする（読み取り専用に縮退）。
